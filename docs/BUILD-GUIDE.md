# Ore Drift: build and publish guide for Android

> This started as the guide the project was built from. It was moved here from the repository's front-page README. Where it says "README.md", read "this file". **Updated Nov 2026 (version 0.5.0):** sections 3 to 5 and 8 to 11 now describe the game as it is today (15 upgrades, flyers, weekly missions, 72 commendations, skins, the relocate cost, the save format). Sections 1, 2, 6, 7 and 9 are still the original build instructions, with small corrections. For the current state of the project see the main [README](../README.md).

Ore Drift is a space-mining idle clicker. You tap an asteroid, hire auto-miners, install upgrades, catch comets, finish daily missions, and relocate to richer belts for permanent bonuses.

This file is written for Claude Code. It describes the game completely, then gives the steps and prompts to turn it into a signed Android app you can publish on Google Play.

A working web prototype is included as `ore-drift.html`. **Put it in the project as `reference/ore-drift.html`.** Every number in this README matches that file. Port it faithfully, and use it to check behavior when anything is unclear.

---

## 0. How to use this file

1. Create an empty folder, for example `ore-drift/`, and put this `README.md` in it.
2. Create `reference/` and put `ore-drift.html` inside it.
3. Run `claude` in that folder.
4. Paste the prompts from section 9, one at a time, in order. Check each result before moving on.

Things only you can do (Claude Code cannot): install Android Studio, create the Google Play developer account, recruit testers, and upload the final file in Play Console.

## 1. Technology

| Layer | Choice | Why |
|---|---|---|
| Game code | Vanilla JavaScript (ES modules), no framework | The prototype is already vanilla JS. A framework adds nothing here. |
| Bundler | Vite | Fast dev server, simple static build into `dist/` |
| Rendering | HTML + CSS for UI, Canvas 2D for the asteroid scene | Already working and light on the battery |
| Native wrapper | Capacitor | Packages the web build as a real Android app and gives access to native plugins |
| Storage | `@capacitor/preferences` (falls back to `localStorage` in a browser) | More durable than WebView `localStorage`, which Android can clear |
| Audio | Web Audio API, synthesized beeps | No audio files to ship |
| Fonts | Self-hosted through `@fontsource` packages | The app must work offline. Do not load Google Fonts from the network. |
| Tests | Vitest for the pure game logic | Economy bugs are easy to introduce and hard to spot by eye |

Alternative: a Trusted Web Activity (Bubblewrap) wraps a hosted PWA instead. It needs a live website and gives no native plugins. Capacitor is recommended because the game should work offline and use haptics and notifications.

### Requirements on your computer

Check the [Capacitor environment setup page](https://capacitorjs.com/docs/next/getting-started/environment-setup) for current versions. At the time of writing it lists:

- Node.js 24 or newer
- A current Android Studio (it bundles the JDK it needs)
- An Android SDK platform installed from Android Studio's SDK Manager
- Git

## 3. Game rules (exact numbers)

### 3.1 Resources and display

- One currency: **ore**, measured in tonnes (`t`). Fractions accrue silently; the big readout shows `floor(ore)` below 1,000.
- Number format: below 999.5 show an integer from 100 up, otherwise one decimal (`0.1`, `15`, `999`). Above that use suffixes `K M B T Qa Qi Sx Sp Oc No Dc` with 2 decimals under 10, 1 decimal under 100, else none (`1.23K`, `15.4M`, `812B`). Rounding up to 1000 rolls over to the next suffix (`999.999K` becomes `1.00M`). Past `Dc` use exponent form.

### 3.2 Vessels (auto-miners)

Cost of the next unit: `base * 1.15 ^ owned`.
Cost of `n` units at once: `ceil(unitCost * (1.15^n - 1) / 0.15)`.
"Max" buys the most you can afford, capped at 1000 per press, and always at least 1 (shown disabled if unaffordable).

| id | Name | Base cost | Base output (t/s each) |
|---|---|---|---|
| drone | Mining Drone | 15 | 0.1 |
| laser | Laser Rig | 100 | 1 |
| tug | Tug Crew | 1,100 | 8 |
| barge | Ore Barge | 12,000 | 47 |
| refinery | Refinery Ship | 130,000 | 260 |
| foundry | Orbital Foundry | 1,400,000 | 1,400 |
| collector | Stellar Collector | 20,000,000 | 7,800 |

**Milestones:** owning 10, 25, 50, 100, 150 and 200 of one vessel each doubles that vessel's output (they stack, so 200 owned is x64).

**Reveal rule:** the first vessel is always visible. Others appear once this run's total mined reaches 40% of their base cost. Show exactly one locked "Unknown vessel" teaser after the last revealed one.

### 3.3 Upgrades (one-time purchases, reset on relocate)

An upgrade is listed once this run's total mined reaches 30% of its cost. The tab shows the affordable and next few ones, then "N installed, M left" and one locked "Unknown upgrade" teaser.

| id | Name | Cost | Effect |
|---|---|---|---|
| bits | Carbide Bits | 100 | tap x2 |
| tune1 | Fleet Tuning I | 2,500 | all vessels x1.25 |
| uplink | Drone Uplink | 8,000 | each tap also gives 5% of current ore/s |
| plasma | Plasma Tips | 40,000 | tap x2 |
| tune2 | Fleet Tuning II | 600,000 | all vessels x1.5 |
| hammer | Resonance Hammer | 8,000,000 | tap x3 |
| uplink2 | Swarm Uplink | 50,000,000 | each tap also gives another 10% of ore/s |
| tune3 | Fleet Tuning III | 300,000,000 | all vessels x2 |
| pulse | Gravity Pulse | 5,000,000,000 | tap x5 |
| tune4 | Fleet Tuning IV | 200,000,000,000 | all vessels x2 |
| uplink3 | Quantum Uplink | 2,000,000,000,000 | each tap also gives another 25% of ore/s |
| tune5 | Fleet Tuning V | 50,000,000,000,000 | all vessels x2.5 |
| singular | Singularity Drill | 200,000,000,000,000 | tap x10 |
| tune6 | Fleet Tuning VI | 10,000,000,000,000,000 | all vessels x3 |
| tune7 | Fleet Tuning VII | 3,000,000,000,000,000,000 | all vessels x4 |

### 3.4 Output formulas

```
vesselOutput  = sum over vessels( owned * baseRate * milestoneMultiplier(owned) )
prodMult      = (product of owned "tune" upgrades) * surveyMult * achMult * iapMult
ops (ore/s)   = vesselOutput * prodMult * (frenzy ? 7 : 1)
tapValue      = (product of owned "tap" upgrades) * surveyMult * achMult * iapMult * (frenzy ? 7 : 1)
                + ops * (sum of owned "uplink" fractions)
surveyMult    = 1 + 0.10 * surveyPower   // power = the bonus steps earned by relocating (S.power)
achMult       = 1 + (sum of the bonus of every commendation earned)   // 1% each for the original 32, 0.5% each for the 40 added later
iapMult       = 1.25 once the Prospector boost has been bought (shop), else 1
```

Every tap adds `tapValue` ore. Every frame adds `ops * dt` ore.

### 3.5 Offline earnings

When the app opens after being closed (or the page was hidden for more than 60 seconds):

```
offlineOre = ops(without frenzy) * min(secondsAway, 8 hours) * 0.5
```

Absences under 2 minutes show a toast: "Away 3 m. Your fleet mined +X t at half rate." (with "(capped at 8 h)" when the cap applied). Longer ones show a welcome-back card (time away, ore gained, whether the hold was full). When rewarded ads are available the player can watch one to double the offline earnings.

### 3.6 Relocate (prestige)

- Bonus steps gained now: `floor(sqrt(totalMinedThisRun / stepCost))`, where `stepCost = 1,000,000 * (1 + stepsHeld / 10) ^ 3`. Holding more steps makes the next ones dearer, so a stronger fleet cannot spam relocations. Each step adds +10% to output and taps (the survey bonus, `S.power`).
- A relocation always gives exactly **1 survey point** (`S.points`), however big the run. Survey points are the currency for skins (3.14). The bonus is what grows with a bigger run, and it is tracked separately, so spending points never lowers it. A save from before this split starts with `power = points`.
- Relocate needs at least 1 point. It requires a second tap to confirm ("Tap again to relocate", resets after 4 seconds).
- It resets: ore, this-run total, vessels, upgrades. It keeps: survey points, the survey bonus, lifetime ore, taps, relocation count, commendations, missions, streak, stats, sound setting.
- Each point adds +10% to all vessel output and taps. Spare points can also be spent on cosmetic skins (3.14); spending never lowers the bonus, which always counts every point earned (`S.points`; `S.spent` only tracks what was spent).
- The Belt tab shows how much more ore the next point needs: `(gain+1)^2 * pointCost`.

### 3.7 Frenzy

A timed x7 multiplier on both ore/s and tap value. Starting a frenzy extends the timer (`max(now, current end) + seconds`), capped at 120 seconds from now. The timer is saved as an absolute timestamp. Offline earnings ignore it. While active: a pill in the header shows "x7 for Ns" and the asteroid veins glow brighter.

### 3.8 Flyers: supply ships, comets and the rubber duck

- First flyer appears 25 seconds after the app starts. After a flyer leaves uncaught: next in 40 to 90 seconds. After one is caught: next in 50 to 110 seconds. On "Meteor weekend" they come twice as often (3.13).
- A flyer crosses the scene in 8 seconds, from a random side, drifting on a gentle sine path at about 30% of the scene height (kept clear of the toast at the top). It has a trail and a ring. Each kind looks and sounds different: a supply ship has a cyan ring and a horn, a comet is an orange glow, a duck is yellow.
- Tap within 44 px of it to catch it (this takes priority over a tap on the asteroid). Keyboard: press `C`.
- Which kind: 60% supply ship, 40% comet; two comets in a row are always followed by a supply ship. About 3% of flyers are a **rubber duck** instead (3.15).
- **Supply ship:** a 30-second frenzy (x7), stacking up to the 120 second cap.
- **Comet:** a random 5 to 25 minutes of current no-frenzy output, at least 300 t (x2 on "Rich comets" days).
- Catching any flyer counts toward the comet mission and the flyer commendations.

### 3.9 Daily supply drop

- Claimable once per local calendar day.
- Streak: claiming the day after the previous claim continues it (`streak + 1`). Missing a day restarts at 1.
- Reward: `max(600*f, ops(no frenzy) * 60 * 15 * f)` where `f = 1 + 0.25 * (min(streakDay, 7) - 1)`. So day 1 pays x1 and day 7 onward pays x2.5.
- UI: seven numbered squares. Filled squares are completed streak days. The square for today's claim has an outline.

### 3.10 Daily missions

Three missions per local day, plus a cache. Missions are generated from the date so a given day always has the same three types.

- Seed: FNV-1a hash of the string `YYYY-MM-DD` (local date), fed to a mulberry32 random generator.
- Shuffle `[tap, mine, buy, comet]` with Fisher-Yates and take the first three.
- Targets:
  - tap: one of 150, 250, 400
  - mine: `niceRound(max(3000, lifetimeOre * 0.04))` (round to 2 significant figures)
  - buy: 8 to 20 vessels (counts units bought, including bulk buys)
  - comet: 2 to 4
- Progress counts everything except reward ore. "Mine" also counts offline earnings.
- Reward per mission: `max(400, ops(no frenzy) * 60 * 8)` (8 minutes of output).
- Daily cache: opens after all three missions are claimed. Pays `max(2500, ops * 60 * 25)` plus a 60-second frenzy.
- At local midnight, missions regenerate and unclaimed ones are lost. The tab shows "Xh Ym left".
- Reward ore counts toward lifetime and this-run totals but not toward the "mine" mission.
- **Swapping:** a mission that is not finished can be swapped for a mission of a type not on today's list. The first swap each day is free; later ones need a bonus ad (free once ads are removed).

**Weekly missions** (a new set every Monday, local time): three missions of different types out of tap, mine, comet, buy and "complete N daily missions".
- Targets: tap = a daily target x 7, mine = `niceRound(max(30,000, lifetimeOre * 0.25))`, buy = 60 to 100 vessels, comet = 12 to 20 flyers, daily = 10 to 14 daily missions.
- Reward per mission: an hour of current output, at least 5,000 t. The first weekly swap each week is free, like the daily one.

### 3.11 Commendations (achievements)

72 in 27 chains. A chain is one tile with up to five tiers (Bronze, Silver, Gold, Platinum, and a top one for a few). Earning a tier:
- gives a permanent bonus to all output and taps and survives relocation: +1% each for the original 32, +0.5% each for the 40 added later;
- shows the commendation banner (it does **not** pay anything by itself);
- sets aside a one-time **ore gift** (3, 8, 20 or 45 minutes of current output by tier, at least 250 / 600 / 1,500 / 4,000 t) that the player claims on the Goals tab, one chain at a time or all at once. The amount is fixed when the tier is earned.

They are checked continuously. The number earned sets the rank: Rookie 0, Prospector 5, Miner 12, Foreman 20, Baron 32, Tycoon 45, Legend 58. Nine chains are secret. They are not shown at all until earned (no placeholder tile), and the total number of commendations is hidden too: the Goals tab and the logbook show just the number earned until every secret one has been found, and only then "N / 72".

| Group | Chains (tier thresholds) |
|---|---|
| Taps | Tapping (100, 1,000, 10,000, 100,000), Tap power (100, 10,000, 1M), Night owl (secret) |
| Ore | Lifetime ore (1,000, 1M, 1B, 1T, 1Qa), Hoard (secret) |
| Output | Output rate, no frenzy (100, 10,000, 1M, 100M t/s), Time away (secret) |
| Fleet | Fleet size (10, 50, 150, 400, 1,000), Vessel kinds (3, 5, 7), One kind (50, 100, 200) |
| Upgrades | Upgrades in one run (3, 6, 10, 15) |
| Belts | Relocations (1, 5, 10, 20), Rings, Spectrum and Bare hands (secret) |
| Survey | Survey bonus reached (+100%, +500%, +2,000%, +10,000%) |
| Flyers | Flyers caught (1, 25, 100), Supply ships (10, 50, 200), Comets (10, 50, 200), Eagle eye and Overdrive (secret) |
| Missions | Missions done (3, 30, 100), Daily caches (1, 7, 30) |
| Supply | Best supply streak (3, 7, 30 days), Supply drops claimed (10, 50, 150) |
| Collection | Commendations earned (10, 25, 45), Old School (secret) |

Locked ones show a progress bar and "value / target". The list has three views: by type (all chains, grouped), next up (closest to done) and earned.

### 3.12 Pacing target (a regression check)

A simulated player who buys the best-value item every second reaches roughly: 10K total ore at 8 minutes, 100K at 19 minutes, 1M (the first bonus step) at 36 minutes, 10M at 66 minutes, 1B at about 200 minutes. Keep the economy within about 15% of this unless you deliberately rebalance. The same simulated player (3 taps a second) needs about 30 minutes for the first bonus step, 22 minutes for the 10th, 17 for the 25th, 13 for the 50th and 11 for the 100th (counting steps held; a relocation can give several). Without the growing point cost (3.6) the 100th took only 2.5 minutes, which made relocating easy to spam.

### 3.13 Weekly events

Two events follow the player's local calendar (no server): **Meteor weekend** (Saturday and Sunday) makes flyers come twice as often, and **Rich comets** (Wednesday) makes comets drop double ore. The header shows a pill with the event name, and the Goals tab shows the next one.

### 3.14 Cosmetic skins

Skins change how the game looks and nothing else. They are bought with spare survey points (`points - spent`; a relocation gives exactly 1), worn per slot, and kept through relocation. A skin can be worn only if owned, and `spent` can never exceed `points` (the save loader enforces both).
- **Asteroid** (11): the colours of the seven other belts (2 points each), plus Gilded, Neon Core, Rose Quartz and Void (6 each). The shape still follows the belt.
- **Fleet paint** (5): Midnight, Copper, Emerald (4 each), Crimson (6), Gold fleet (10).
- **Sky** (4): Warm stars (3), Aurora, Violet nebula and Deep blue (6 each, with a coloured glow behind the asteroid).
Costs are constants in `src/data.js` (`SKINS`).

### 3.15 Easter eggs

- **Rubber duck:** 3% of flyers. It pays 30 to 60 minutes of output (at least 2,000 t) and a 20 second x7 boost, quacks, and counts as a flyer caught. A hidden "Rubber ducks" line appears in the logbook after the first.
- **8-bit mode:** swipe up, up, down, down, left, right, left, right on the asteroid, then tap twice (keyboard: arrow keys, then B and A; at most 3 seconds between steps). For 60 seconds the canvas is drawn at low resolution and scaled up with hard pixels, the UI gets a pixel font, square corners and scanlines, and sound effects become square waves. It is never saved, but switching it on earns the secret "Old School" commendation. Chapter 9 of the Captain's journal has a cryptic clue to the code.

## 4. Screens and design

### 4.1 Layout (portrait only)

- **Header:** "ORE IN HOLD" label, large ore number with a small orange `t`, then a row with `+X t/s`, `tap +Y`, a bonus pill (`+N% bonus` from the survey bonus, commendations and the shop boost, abbreviated like ore once it passes 1,000%), the frenzy pill, an event pill, and (briefly) the 8-bit countdown.
- **Stage:** canvas, about one third of the screen height. A rotating asteroid with glowing ore veins, craters, twinkling stars, small ships that orbit it (one per owned vessel, max 14, with brief mining beams), tap particles and floating `+value` text, and the flyers. Skins recolour the asteroid, the ships and the sky.
- **Toast:** an overlay at the top of the stage. Messages queue (max 4) and show one at a time for about 3.2 seconds (tap to dismiss). Commendations use their own banner.
- **Tabs (bottom nav, icons only, with accessible names):** Fleet (rocket), Upgrades (chevrons), Goals (trophy), Belt (ringed planet), Captain's log (logbook), and Shop (bag, hidden while `SHOP_ENABLED` is false). A small orange dot marks a tab with something ready.
  - Fleet: buy mode switch (x1, x10, Max) and one card per vessel.
  - Upgrades: one card per visible upgrade, plus "N installed, M left".
  - Goals: next event, supply drop, daily missions, weekly missions, daily cache, commendations (with Claim buttons for their ore gifts).
  - Belt: a switcher with three views. **Relocate** (survey points, the bonus you gain, what you lose, the Relocate button with a confirm tap), **Cosmetics** (skins, 3.14) and **Settings** (sound, music, vibration, how to play, reminders on Android, ad privacy choices when required, wipe save with a confirm tap, Privacy policy, version).
  - Captain's log: the Captain's journal (10 chapters that open strictly in order: each needs its own goal and every earlier chapter open) and the logbook of stats and rank.
  - Shop: optional purchases through Google Play.
- **Overlays:** a four-card how-to-play (first launch, and again from Settings), the Captain's journal, the in-app privacy policy (the same text as the hosted page), the welcome-back summary, and the splash.
- Buttons have a 44 to 48 px minimum touch size. Affordable buy buttons are filled orange, others outlined.

## 5. Save data

- Key `oredrift.v1`, one JSON object. Save every 5 seconds, when the app goes to the background, and after every purchase or claim.
- Fields: `ore, total, allTime, taps, points, power, runs, owned{id:count}, ups{id:true}, last (ms), sound, music, haptics, notify, ach{id:true}, gifts{achId:ore}, stats{comets, missions, best, ships, drops, chests, capped, night, bare, bestRun, overdrive, played, peak, ducks}, streak, lastSupply ("YYYY-MM-DD"), daily{day, missions[{type,target,progress,claimed}], chest, swaps}, weekly{week, missions[...], swaps}, frenzyUntil (ms), podReadyAt (ms), iap{removeAds, starter, boost}, granted[order ids], journalSeen, tutorial, spent, skins{id:true}, look{rock, fleet, sky}`.
- On load, validate everything: numbers must be finite and non-negative, unknown ids dropped, `daily.missions` and `weekly.missions` must have exactly 3 valid entries, `spent` can never exceed `points`, only owned skins of the right slot can be worn, `gifts` only for earned commendations, `lastSupply` must match `\d{4}-\d{2}-\d{2}`. A corrupt save must never crash the game; fall back to defaults for the bad field.
- Days use the device's local date. If the saved `daily.day` is not today, generate new missions; if `weekly.week` is not this week's Monday, generate new weekly missions.
- An older save that lacks newer fields loads with their defaults. A save that already has progress counts as having seen the tutorial.

## 6. What changes when it becomes a real app

1. **Storage:** wrap load/save so it uses `@capacitor/preferences` on device and `localStorage` in a browser.
2. **Lifecycle:** on `App` `pause`, save immediately. On `resume`, compute offline earnings from the saved `last` timestamp. Never run the game loop while paused.
3. **Haptics:** replace `navigator.vibrate` with `@capacitor/haptics` (light impact on tap, medium on comet catch).
4. **Notifications (optional, ask the player first):** `@capacitor/local-notifications`. One daily reminder when the supply drop is ready, and one when offline earnings reach the 8-hour cap. Request permission only after the player enables it in Settings.
5. **Safe areas and bars:** keep `viewport-fit=cover`, pad the layout with `env(safe-area-inset-*)`, use `@capacitor/status-bar` to match `--ink`, and use `@capacitor/splash-screen` with the dark background.
6. **Back button:** from a non-Fleet tab, go to Fleet. On Fleet, exit the app.
7. **Orientation:** lock to portrait in `AndroidManifest.xml` (`android:screenOrientation="portrait"`).
8. **Audio:** create the `AudioContext` on the first tap (browser rule). Add a master sound toggle (already in Settings).
9. **Offline:** nothing may need the network. Self-host the fonts.
10. **Version in Settings:** show the app version and open the privacy policy. Done: the policy opens inside the app, built from `docs/index.html` (the same file GitHub Pages serves), with a link to the web copy.

### Monetization

Ads are in: a small banner under the tab bar plus optional rewarded ads through AdMob ("watch an ad to double your offline earnings" and the cargo pod). Never show forced ads during taps. A Shop for optional purchases through Google Play Billing is built but switched off (`SHOP_ENABLED` in `src/main.js`) until the app can sell for real. If you add ads, purchases or any analytics, the privacy policy and the Data safety form in Play Console must say so.

## 7. Build the Android app

Run these in the project folder. Claude Code can run most of them for you.

```bash
npm create vite@latest . -- --template vanilla
npm install
npm install @capacitor/core @capacitor/android @capacitor/app @capacitor/haptics @capacitor/preferences \
  @capacitor/status-bar @capacitor/splash-screen @capacitor/local-notifications \
  @capacitor-community/admob @capgo/native-purchases \
  @fontsource/big-shoulders-display @fontsource/ibm-plex-sans @fontsource/ibm-plex-mono @fontsource/press-start-2p
npm install -D @capacitor/cli @capacitor/assets vitest

npx cap init "Ore Drift" com.YOURNAME.oredrift --web-dir dist
npm run build
npx cap add android
npx cap sync android
npx cap open android      # opens Android Studio; press Run to try it on an emulator or phone
```

**Choose the application ID once.** `com.YOURNAME.oredrift` cannot be changed after the app is published. Use a reverse-domain style name you control.

### Icons and splash

Put source images in `assets/`: `icon-only.png` (1024x1024), `icon-foreground.png`, `icon-background.png`, `splash.png` (2732x2732) and `splash-dark.png`. Then:

```bash
npx capacitor-assets generate --android --assetPath assets
```

The icon is a flat orange crystal on the `--ink` background, and the splash is the crystal on an orbit ring over a starfield with the title and tagline. Draw original designs; do not copy another game's art. Android 12 and newer ignore a full-screen splash picture at launch (they show an icon on a colour), so the launch theme in `styles.xml` uses an empty icon on navy, and an in-app splash (`index.html`, `src/main.js`) fades out when the game is ready.

### Target API level

Google Play requires new apps and updates to target **API 36 (Android 16)** from August 31, 2026 ([Android developer docs](https://developer.android.com/google/play/requirements/target-sdk)). In `android/variables.gradle` set `targetSdkVersion = 36` and a matching `compileSdkVersion`. Check the Capacitor version you installed supports it, and update Capacitor if not.

### Signing and the release bundle

Play wants an **Android App Bundle (.aab)**, not an APK.

```bash
# 1. Create an upload key ONCE. Back it up. Losing it is painful.
keytool -genkey -v -keystore upload-keystore.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000

# 2. Put the passwords in android/keystore.properties (add it and the .jks to .gitignore)
# 3. Read keystore.properties in android/app/build.gradle (signingConfigs.release)

# 4. Build
npm run build && npx cap sync android
cd android && ./gradlew bundleRelease
# output: android/app/build/outputs/bundle/release/app-release.aab
```

Increase `versionCode` in `android/app/build.gradle` for every upload (1, 2, 3...; it can never repeat). Set `versionName` to something like `0.5.0` while the app is in testing and `1.0.0` when it reaches production (only `versionCode` is checked by Play; the name is a label), and keep the `package.json` version the same, because Settings shows that one. Built APKs are named `ore-drift.apk`. Turn on Play App Signing when you create the app in Play Console; your keystore then only serves as the upload key.

Never commit the keystore or its passwords.

## 8. Publish on Google Play

### One-time account setup

1. Create a Google Play developer account at play.google.com/console. There is a one-time registration fee, and Google asks you to verify your identity. Confirm the current fee and steps on the sign-up page.
2. Choose personal or organization. This matters for testing rules (below).

### Testing rule for new personal accounts

Personal developer accounts created after November 13, 2023 must run a **closed test with at least 12 testers opted in for 14 consecutive days** before they can apply for production access. Testers who opt out and back in restart the count. When the 14 days are done, click "Apply for production" on the Play Console dashboard and answer the questions about the test, the app and its readiness ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/14151465)). Start recruiting testers early (friends, family, online communities) because this is the slowest step.

Organization accounts follow different rules; check Play Console Help.

### Create the app and complete these sections

- **App details:** name `Ore Drift` (check it is not taken or confusingly close to another game), default language, App or Game = Game, Free or Paid.
- **Store listing:**
  - Short description, 80 characters max. Example: "Tap an asteroid, hire miners, catch comets, and build a mining empire."
  - Full description, up to 4,000 characters.
  - App icon 512x512 PNG.
  - Feature graphic 1024x500.
  - Phone screenshots (at least 2; take them from the real app in portrait). Ready-made ones are in `store/screenshots/`.
  - Product icons for in-app products are in `store/product-icons/`. The full listing text and every form answer are drafted in `store/listing.md`.
- **App content (Play Console asks for each):**
  - Privacy policy URL. Host a simple page. If the app collects no data, say exactly that.
  - Ads declaration (yes if you added AdMob).
  - Content rating questionnaire (expect a low rating for this game).
  - Target audience and content. Pick 13+ or all ages carefully; targeting children brings extra Families policy rules.
  - Data safety form. Accurate answers about what the app collects and shares. The game keeps its save on the device, but the AdMob ads SDK collects and shares an advertising ID, approximate location, ad interactions, crash logs and diagnostics, so the answer is **yes**, and the Advertising ID declaration is yes. The exact entries are in `store/listing.md`.
- **Release:** create a **closed testing** release, upload the `.aab`, add your tester list or Google Group, and send testers the opt-in link.
- After the 14 days, apply for production, then create the production release and submit it for review. Reviews can take from a few hours to about a week for a first release (Google does not promise a time).
- In-app products (when the shop is switched on): create the six one-time products in Monetize with Play, make each **Active**, and answer the digital purchases questions. Steps and texts are in `store/listing.md`.

### Updates later

Increase `versionCode`, rebuild the `.aab`, upload to a new release. Keep `targetSdkVersion` at or above the current requirement.

## 11. Known prototype limits to fix in the real app

- Progress is stored per device only. Android's automatic backup may restore it on a new phone, but there is no live sync. If you want cloud saves later, add Google Play Games Services (it needs a native plugin, a consent screen and updates to the Data safety form and the privacy policy).
- Numbers above about 1e300 are not handled (the game will not reach that).
- Changing the device clock can claim daily rewards early. For a single-player game this is acceptable; if it matters, use a server time check.
- The relocate cost (3.6), upgrade costs and skin prices are tuned by simulation and by feel only. Playtest the first hour, the first relocation and the first twenty with real people.
