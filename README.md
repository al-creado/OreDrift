# Ore Drift: build and publish guide for Android

Ore Drift is a space-mining idle clicker. You tap an asteroid, hire auto-miners, install upgrades, catch comets, finish daily missions, and relocate to richer belts for permanent bonuses.

This file is written for Claude Code. It describes the game completely, then gives the steps and prompts to turn it into a signed Android app you can publish on Google Play.

A working web prototype is included as `ore-drift.html`. **Put it in the project as `reference/ore-drift.html`.** Every number in this README matches that file. Port it faithfully, and use it to check behavior when anything is unclear.

---

## 0. How to use this file

1. Create an empty folder, for example `ore-drift/`, and put this `README.md` in it.
2. Create `reference/` and put `ore-drift.html` inside it.
3. Run `claude` in that folder.
4. Paste the prompts from section 9, one at a time, in order. Check each result before moving on.

Things only you can do (Claude Code cannot): install Android Studio, create the Google Play developer account, recruit testers, and upload the final file in Play Console.

## 1. Technology

| Layer | Choice | Why |
|---|---|---|
| Game code | Vanilla JavaScript (ES modules), no framework | The prototype is already vanilla JS. A framework adds nothing here. |
| Bundler | Vite | Fast dev server, simple static build into `dist/` |
| Rendering | HTML + CSS for UI, Canvas 2D for the asteroid scene | Already working and light on the battery |
| Native wrapper | Capacitor | Packages the web build as a real Android app and gives access to native plugins |
| Storage | `@capacitor/preferences` (falls back to `localStorage` in a browser) | More durable than WebView `localStorage`, which Android can clear |
| Audio | Web Audio API, synthesized beeps | No audio files to ship |
| Fonts | Self-hosted through `@fontsource` packages | The app must work offline. Do not load Google Fonts from the network. |
| Tests | Vitest for the pure game logic | Economy bugs are easy to introduce and hard to spot by eye |

Alternative: a Trusted Web Activity (Bubblewrap) wraps a hosted PWA instead. It needs a live website and gives no native plugins. Capacitor is recommended because the game should work offline and use haptics and notifications.

### Requirements on your computer

Check the [Capacitor environment setup page](https://capacitorjs.com/docs/next/getting-started/environment-setup) for current versions. At the time of writing it lists:

- Node.js 24 or newer
- A current Android Studio (it bundles the JDK it needs)
- An Android SDK platform installed from Android Studio's SDK Manager
- Git

## 3. Game rules (exact numbers)

### 3.1 Resources and display

- One currency: **ore**, measured in tonnes (`t`). Fractions accrue silently; the big readout shows `floor(ore)` below 1,000.
- Number format: below 999.5 show an integer from 100 up, otherwise one decimal (`0.1`, `15`, `999`). Above that use suffixes `K M B T Qa Qi Sx Sp Oc No Dc` with 2 decimals under 10, 1 decimal under 100, else none (`1.23K`, `15.4M`, `812B`). Rounding up to 1000 rolls over to the next suffix (`999.999K` becomes `1.00M`). Past `Dc` use exponent form.

### 3.2 Vessels (auto-miners)

Cost of the next unit: `base * 1.15 ^ owned`.
Cost of `n` units at once: `ceil(unitCost * (1.15^n - 1) / 0.15)`.
"Max" buys the most you can afford, capped at 1000 per press, and always at least 1 (shown disabled if unaffordable).

| id | Name | Base cost | Base output (t/s each) |
|---|---|---|---|
| drone | Mining Drone | 15 | 0.1 |
| laser | Laser Rig | 100 | 1 |
| tug | Tug Crew | 1,100 | 8 |
| barge | Ore Barge | 12,000 | 47 |
| refinery | Refinery Ship | 130,000 | 260 |
| foundry | Orbital Foundry | 1,400,000 | 1,400 |
| collector | Stellar Collector | 20,000,000 | 7,800 |

**Milestones:** owning 10, 25, 50, 100, 150 and 200 of one vessel each doubles that vessel's output (they stack, so 200 owned is x64).

**Reveal rule:** the first vessel is always visible. Others appear once this run's total mined reaches 40% of their base cost. Show exactly one locked "Unknown vessel" teaser after the last revealed one.

### 3.3 Upgrades (one-time purchases, reset on relocate)

An upgrade is listed once this run's total mined reaches 30% of its cost.

| id | Name | Cost | Effect |
|---|---|---|---|
| bits | Carbide Bits | 100 | tap x2 |
| tune1 | Fleet Tuning I | 2,500 | all vessels x1.25 |
| uplink | Drone Uplink | 8,000 | each tap also gives 5% of current ore/s |
| plasma | Plasma Tips | 40,000 | tap x2 |
| tune2 | Fleet Tuning II | 600,000 | all vessels x1.5 |
| hammer | Resonance Hammer | 8,000,000 | tap x3 |
| uplink2 | Swarm Uplink | 50,000,000 | each tap also gives another 10% of ore/s |
| tune3 | Fleet Tuning III | 300,000,000 | all vessels x2 |
| pulse | Gravity Pulse | 5,000,000,000 | tap x5 |

### 3.4 Output formulas

```
vesselOutput  = sum over vessels( owned * baseRate * milestoneMultiplier(owned) )
prodMult      = (product of owned "tune" upgrades) * surveyMult * achMult
ops (ore/s)   = vesselOutput * prodMult * (frenzy ? 7 : 1)
tapValue      = (product of owned "tap" upgrades) * surveyMult * achMult * (frenzy ? 7 : 1)
                + ops * (sum of owned "uplink" fractions)
surveyMult    = 1 + 0.10 * surveyPoints
achMult       = 1 + 0.01 * commendationsEarned
```

Every tap adds `tapValue` ore. Every frame adds `ops * dt` ore.

### 3.5 Offline earnings

When the app opens after being closed (or the page was hidden for more than 60 seconds):

```
offlineOre = ops(without frenzy) * min(secondsAway, 8 hours) * 0.5
```

Show a toast: "Away 3 h 12 m. Your fleet mined +X t at half rate." Add "(capped at 8 h)" when the cap applied.

### 3.6 Relocate (prestige)

- Survey points gained now: `floor(sqrt(totalMinedThisRun / 1,000,000))`.
- Relocate needs at least 1 point. It requires a second tap to confirm ("Tap again to relocate", resets after 4 seconds).
- It resets: ore, this-run total, vessels, upgrades. It keeps: survey points, lifetime ore, taps, relocation count, commendations, missions, streak, stats, sound setting.
- Each point adds +10% to all vessel output and taps.
- The Belt tab shows how much more ore the next point needs: `(points+1)^2 * 1,000,000`.

### 3.7 Frenzy

A timed x7 multiplier on both ore/s and tap value. Starting a frenzy extends the timer (`max(now, current end) + seconds`), capped at 120 seconds from now. The timer is saved as an absolute timestamp. Offline earnings ignore it. While active: a pill in the header shows "x7 for Ns" and the asteroid veins glow brighter.

### 3.8 Comets

- First comet appears 25 seconds after the app starts. After a comet leaves uncaught: next in 40 to 90 seconds. After one is caught: next in 50 to 110 seconds.
- A comet crosses the scene in 8 seconds, from a random side, drifting on a gentle sine path at about 30% of the scene height (kept clear of the toast at the top). It has a trail and a pulsing ring.
- Tap within 44 px of it to catch it (this takes priority over a tap on the asteroid). Keyboard: press `C`.
- Reward, chosen at random: 70% a 30-second frenzy ("Rich vein!"), 30% a cargo pod worth 13 minutes of current output, minimum 300 t.
- Catching one counts toward the comet mission and the comet achievements.

### 3.9 Daily supply drop

- Claimable once per local calendar day.
- Streak: claiming the day after the previous claim continues it (`streak + 1`). Missing a day restarts at 1.
- Reward: `max(600*f, ops(no frenzy) * 60 * 15 * f)` where `f = 1 + 0.25 * (min(streakDay, 7) - 1)`. So day 1 pays x1 and day 7 onward pays x2.5.
- UI: seven numbered squares. Filled squares are completed streak days. The square for today's claim has an outline.

### 3.10 Daily missions

Three missions per local day, plus a cache. Missions are generated from the date so a given day always has the same three types.

- Seed: FNV-1a hash of the string `YYYY-MM-DD` (local date), fed to a mulberry32 random generator.
- Shuffle `[tap, mine, buy, comet]` with Fisher-Yates and take the first three.
- Targets:
  - tap: one of 150, 250, 400
  - mine: `niceRound(max(3000, lifetimeOre * 0.04))` (round to 2 significant figures)
  - buy: 8 to 20 vessels (counts units bought, including bulk buys)
  - comet: 2 to 4
- Progress counts everything except reward ore. "Mine" also counts offline earnings.
- Reward per mission: `max(400, ops(no frenzy) * 60 * 8)` (8 minutes of output).
- Daily cache: opens after all three missions are claimed. Pays `max(2500, ops * 60 * 25)` plus a 60-second frenzy.
- At local midnight, missions regenerate and unclaimed ones are lost. The tab shows "Xh Ym left".
- Reward ore counts toward lifetime and this-run totals but not toward the "mine" mission.

### 3.11 Commendations (achievements)

32 in total. Each gives a permanent +1% to all output and taps, and survives relocation. They are checked continuously. When one unlocks, show the toast "Commendation earned: NAME. All output +1%." and play a short sound.

| Group | Name and threshold |
|---|---|
| Taps (lifetime) | First Strikes 100, Steady Hands 1,000, Jackhammer 10,000, Rock Breaker 100,000 |
| Lifetime ore | First Haul 1,000, Cargo Run 1M, Heavy Freight 1B, Belt Baron 1T |
| Vessels owned at once | Small Crew 10, Proper Fleet 50, Armada 150, Swarm 400 |
| Kinds of vessel owned | Mixed Fleet 3, Full Roster 5, One of Each 7 |
| Upgrades in one run | Tooled Up 3, Fully Fitted 9 |
| Relocations | New Horizons 1, Belt Hopper 5, Survey Veteran 10 |
| Comets caught | Sky Watcher 1, Comet Hunter 25, Vein Chaser 100 |
| Missions completed | Clocking In 3, Regular 30, Lifer 100 |
| Best supply streak (days) | Back Again 3, Week Out 7, Long Haul 30 |
| Output rate, no frenzy (t/s) | Humming 100, Roaring 10,000, Unstoppable 1,000,000 |

Locked ones show a progress bar and "value / target", sorted by closest to done. Earned ones show a check mark and sit at the bottom.

### 3.12 Pacing target (a regression check)

A simulated player who buys the best-value item every second reaches roughly: 10K total ore at 8 minutes, 100K at 19 minutes, 1M (first survey point) at 36 minutes, 10M at 66 minutes, 1B at about 200 minutes. Keep the economy within about 15% of this unless you deliberately rebalance.

## 4. Screens and design

### 4.1 Layout (portrait only)

- **Header:** "ORE IN HOLD" label, large ore number with a small orange `t`, then a row with `+X t/s`, `tap +Y`, a bonus pill (`+N% bonus` from survey points and commendations) and the frenzy pill.
- **Stage:** canvas, about one third of the screen height. A rotating asteroid with glowing ore veins, craters, twinkling stars, small ships that orbit it (one per owned vessel, max 14, with brief mining beams), tap particles and floating `+value` text, and the comet.
- **Toast:** an overlay at the top of the stage. Messages queue (max 4) and show one at a time for about 3.2 seconds (tap to dismiss).
- **Tabs (bottom nav, 4):** Fleet, Upgrades, Goals, Belt. A small orange dot marks a tab with something ready (affordable upgrade, claimable goal, relocate available).
  - Fleet: buy mode switch (x1, x10, Max) and one card per vessel.
  - Upgrades: one card per visible upgrade, plus "N of 9 installed".
  - Goals: supply drop, daily missions and cache, commendations.
  - Belt: relocate, logbook (lifetime ore, this run, taps, vessels, relocations, comets caught, missions done, best streak, commendations), settings (sound on/off, wipe save with a confirm tap).
- Buttons have a 44 to 48 px minimum touch size. Affordable buy buttons are filled orange, others outlined.

## 5. Save data

- Key `oredrift.v1`, one JSON object. Save every 5 seconds, when the app goes to the background, and after every purchase or claim.
- Fields: `ore, total, allTime, taps, points, runs, owned{id:count}, ups{id:true}, last (ms), sound, ach{id:true}, stats{comets,missions,best}, streak, lastSupply ("YYYY-MM-DD"), daily{day, missions[{type,target,progress,claimed}], chest}, frenzyUntil (ms)`.
- On load, validate everything: numbers must be finite and non-negative, unknown ids dropped, `daily.missions` must have exactly 3 valid entries, `lastSupply` must match `\d{4}-\d{2}-\d{2}`. A corrupt save must never crash the game; fall back to defaults for the bad field.
- Days use the device's local date. If the saved `daily.day` is not today, generate new missions.

## 6. What changes when it becomes a real app

1. **Storage:** wrap load/save so it uses `@capacitor/preferences` on device and `localStorage` in a browser.
2. **Lifecycle:** on `App` `pause`, save immediately. On `resume`, compute offline earnings from the saved `last` timestamp. Never run the game loop while paused.
3. **Haptics:** replace `navigator.vibrate` with `@capacitor/haptics` (light impact on tap, medium on comet catch).
4. **Notifications (optional, ask the player first):** `@capacitor/local-notifications`. One daily reminder when the supply drop is ready, and one when offline earnings reach the 8-hour cap. Request permission only after the player enables it in Settings.
5. **Safe areas and bars:** keep `viewport-fit=cover`, pad the layout with `env(safe-area-inset-*)`, use `@capacitor/status-bar` to match `--ink`, and use `@capacitor/splash-screen` with the dark background.
6. **Back button:** from a non-Fleet tab, go to Fleet. On Fleet, exit the app.
7. **Orientation:** lock to portrait in `AndroidManifest.xml` (`android:screenOrientation="portrait"`).
8. **Audio:** create the `AudioContext` on the first tap (browser rule). Add a master sound toggle (already in Settings).
9. **Offline:** nothing may need the network. Self-host the fonts.
10. **Version in Settings:** show the app version and a link to the privacy policy.

### Optional monetization

Only if you want it. The cleanest fit is **rewarded ads** through AdMob: "watch an ad to double your offline earnings" or "watch an ad for a 30-second frenzy". Never show forced ads during taps. If you add ads or any analytics, the privacy policy and the Data safety form in Play Console must say so.

## 7. Build the Android app

Run these in the project folder. Claude Code can run most of them for you.

```bash
npm create vite@latest . -- --template vanilla
npm install
npm install @capacitor/core @capacitor/app @capacitor/haptics @capacitor/preferences \
  @capacitor/status-bar @capacitor/splash-screen @capacitor/local-notifications \
  @fontsource/big-shoulders-display @fontsource/ibm-plex-sans @fontsource/ibm-plex-mono
npm install -D @capacitor/cli @capacitor/assets vitest

npx cap init "Ore Drift" com.YOURNAME.oredrift --web-dir dist
npm run build
npx cap add android
npx cap sync android
npx cap open android      # opens Android Studio; press Run to try it on an emulator or phone
```

**Choose the application ID once.** `com.YOURNAME.oredrift` cannot be changed after the app is published. Use a reverse-domain style name you control.

### Icons and splash

Put source images in `assets/`: `icon-only.png` (1024x1024), `icon-foreground.png`, `icon-background.png`, `splash.png` (2732x2732) and `splash-dark.png`. Then:

```bash
npx @capacitor/assets generate --android
```

Suggested icon: the asteroid with glowing orange veins on the `--ink` background. Draw an original design; do not copy another game's art.

### Target API level

Google Play requires new apps and updates to target **API 36 (Android 16)** from August 31, 2026 ([Android developer docs](https://developer.android.com/google/play/requirements/target-sdk)). In `android/variables.gradle` set `targetSdkVersion = 36` and a matching `compileSdkVersion`. Check the Capacitor version you installed supports it, and update Capacitor if not.

### Signing and the release bundle

Play wants an **Android App Bundle (.aab)**, not an APK.

```bash
# 1. Create an upload key ONCE. Back it up. Losing it is painful.
keytool -genkey -v -keystore upload-keystore.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000

# 2. Put the passwords in android/keystore.properties (add it and the .jks to .gitignore)
# 3. Read keystore.properties in android/app/build.gradle (signingConfigs.release)

# 4. Build
npm run build && npx cap sync android
cd android && ./gradlew bundleRelease
# output: android/app/build/outputs/bundle/release/app-release.aab
```

Increase `versionCode` in `android/app/build.gradle` for every upload (1, 2, 3...). Set `versionName` to something like `1.0.0`. Turn on Play App Signing when you create the app in Play Console; your keystore then only serves as the upload key.

Never commit the keystore or its passwords.

## 8. Publish on Google Play

### One-time account setup

1. Create a Google Play developer account at play.google.com/console. There is a one-time registration fee, and Google asks you to verify your identity. Confirm the current fee and steps on the sign-up page.
2. Choose personal or organization. This matters for testing rules (below).

### Testing rule for new personal accounts

Personal developer accounts created after November 13, 2023 must run a **closed test with at least 12 testers opted in for 14 consecutive days** before they can apply for production access. Testers who opt out and back in restart the count. When the 14 days are done, click "Apply for production" on the Play Console dashboard and answer the questions about the test, the app and its readiness ([Play Console Help](https://support.google.com/googleplay/android-developer/answer/14151465)). Start recruiting testers early (friends, family, online communities) because this is the slowest step.

Organization accounts follow different rules; check Play Console Help.

### Create the app and complete these sections

- **App details:** name `Ore Drift` (check it is not taken or confusingly close to another game), default language, App or Game = Game, Free or Paid.
- **Store listing:**
  - Short description, 80 characters max. Example: "Tap an asteroid, hire miners, catch comets, and build a mining empire."
  - Full description, up to 4,000 characters.
  - App icon 512x512 PNG.
  - Feature graphic 1024x500.
  - Phone screenshots (at least 2; take them from the real app in portrait).
- **App content (Play Console asks for each):**
  - Privacy policy URL. Host a simple page. If the app collects no data, say exactly that.
  - Ads declaration (yes if you added AdMob).
  - Content rating questionnaire (expect a low rating for this game).
  - Target audience and content. Pick 13+ or all ages carefully; targeting children brings extra Families policy rules.
  - Data safety form. Accurate answers about what the app collects and shares. With no analytics, no ads and local-only saves, the answer is "no data collected".
- **Release:** create a **closed testing** release, upload the `.aab`, add your tester list or Google Group, and send testers the opt-in link.
- After the 14 days, apply for production, then create the production release and submit it for review. Reviews can take from a few hours to several days.

### Updates later

Increase `versionCode`, rebuild the `.aab`, upload to a new release. Keep `targetSdkVersion` at or above the current requirement.

## 10. Test checklist before every release

- [ ] Fresh install on a real phone: first tap, first purchase, first upgrade.
- [ ] Close the app, wait a few minutes, reopen: offline earnings toast is correct (half rate).
- [ ] Force close during play: progress is restored within 5 seconds of loss.
- [ ] Change the phone's date to tomorrow: missions regenerate, supply drop is claimable, streak continues. Change to two days ahead: streak resets.
- [ ] Relocate: keeps commendations, missions and streak; resets vessels and upgrades.
- [ ] Comet appears, can be caught by touch, frenzy pill counts down.
- [ ] Airplane mode: everything works, fonts render.
- [ ] Rotate the phone: stays portrait.
- [ ] Back button behaves as in section 6.
- [ ] A corrupt save (edit it by hand) does not crash the app.
- [ ] `npm test` passes. Release bundle installs from the `.aab` using `bundletool` or an internal test track.
- [ ] Version code was increased.

## 11. Known prototype limits to fix in the real app

- Progress is stored per device only. If you want cloud saves later, add Google Play Games Services or a small backend.
- Numbers above about 1e300 are not handled (the game will not reach that).
- Changing the device clock can claim daily rewards early. For a single-player game this is acceptable; if it matters, use a server time check.
- The relocate formula and upgrade costs are tuned by simulation only. Playtest the first hour and the first relocation with real people.
